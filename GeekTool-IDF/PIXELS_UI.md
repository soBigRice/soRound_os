## 入口与职责

`launcher.c:enter_app → app_pixels.enter → pixel_enter` 创建绘图面和两个按钮。
`pixel_field.c/h` 只管理像素位置、弹簧运动和摇动判定，不依赖 LVGL、传感器或堆分配。
`app_pixels.c` 负责真实触摸/IMU、UI、CPU频率锁与生命周期。
标题使用已有 `font_location_24`，保持 y=46；48px共享返回中心为(133,64)。
返回依然由 `launcher.c` 退出应用，BOOT短按锁屏/长按关机不变。

| 操作 | 实际调用与结果 |
| --- | --- |
| 点按/拖动像素区 | `pixel_touch → lv_indev_get_point → pixel_field_touch`；半径65px内方块受径向推力，释放后弹回原位置 |
| 摇动 | `pixel_tick → imu_read_accel → pixel_shake_sample → pixel_field_repattern`；切换下一条色带并散开重排 |
| 配色 | `pixel_action(0)`循环珊瑚花园、海边晴天、薄荷夜色，只改变颜色，保持当前位置及运动 |
| 重聚 | `pixel_action(1) → pixel_field_gather`；清触摸/速度并返回本条色带，不换图、不换色 |
| 返回 | 原共享返回退出；像素区关闭gesture/event冒泡，向右拨动方块不会误退出 |

## 状态、绘制与边界

三个色带来自已确认原型的同一25×15网格与正弦轮廓；间隔14px、方块12px，
中心超出190px圆形安全区的网格不创建。方块运动限制在绘画区域内，不盖住标题、提示和按钮。
spring步长最多40ms；拒绝非有限坐标/时间及区域外输入。收敛后位置精确回到目标，停止更新画面。

`pixel_tick`复用启动器的20ms节拍，不新建任务或定时器。运动步进间隔至少33ms；
这不是实测30FPS。`pixel_field_step`只在方块光栅位置改变时使绘画区域失效，
绘制使用 `LV_EVENT_DRAW_MAIN / lv_draw_rect`；不申请整屏RGB565缓冲或375个LVGL对象。
只有运动且可见时持有 `ESP_PM_CPU_FREQ_MAX` 锁，静止、遮挡和退出释放。

| 生命周期/故障 | 行为 |
| --- | --- |
| 静止 | 仅每50ms读取IMU以等待摇动；不模拟、不重绘、不持有App CPU锁 |
| 锁屏/快捷面板遮挡 | `pixel_visibility(false)`停止采样和运动、清触摸/摇动判定，释放锁 |
| 恢复 | 重置帧/采样时刻，继续尚未收敛的运动，不补算后台时长 |
| 退出/父对象删除 | `pixel_exit / body_deleted`释放唯一场数据和CPU锁，清对象引用；两条路径不重复释放 |
| 无IMU或读失败 | 明确显示“触摸可玩 · 传感器不可用”；触摸、配色、重聚、返回仍可用，读成功后恢复提示 |
| 场内存分配失败 | 显示“内存不足”，禁用配色/重聚；共享返回可用，不采样、不持有锁 |

场数据单次从PSRAM分配，大小由 `sizeof(pixel_field_t)` 确定；不在帧内分配。
色带/配色在本次开机内保留，无新增NVS键、网络请求、声音或依赖。

## 摇动判定

使用项目现有QMI8658加速度接口，单位g。静态重力模长约1，不把普通姿态变化直接当作摇动。
两个模长>1.55g的峰间隔40～250ms，且中间必须观察到<1.3g回落，才触发一次；随后至少900ms冷却，
并要求0.85～1.2g持续300ms才能重装。持续高加速度、过期单次脉冲和坏样本不能不断换图。
本轮复核发现连续高幅值样本会把单次持续冲击当作两峰，已加回落迟滞并补相反用例。
当前采样周期与阈值由主机输入夹具验证，真实摇动手感、误触与触发率待真机验收。
不改共享IMU量程；±2g/16,384LSB每g与现有`imu.c`及
[QMI8658A制造商数据手册Rev A](https://www.qstcorp.com/upload/pdf/202301/13-52-25%20QMI8658A%20Datasheet%20Rev%20A.pdf)一致，2026-10-09核查。

## 字体与防线

16px文案使用 `font_weather_16` 的局部RAM副本挂 `font_cn16` fallback，不修改全局字体。
`gen_font_cn.swift`扫描本页真实字符串，并补U+00B7中点；原415枚16px字形的alpha、字距和基线逐一保持。
`gen_location_font.swift`保留已有生成文件的全部历史码点，再合并当前文案；
原1495枚24px字形逐一保持，新增“块”。

本轮原生缺字检查曾识别U+00B7缺失；字体扫描也发现24px生成器只看当前字符串时会移除“效/生”。
已修正扫描/历史保留条件，没有通过更换分隔符、删除历史字符或重写旧字形基准隐藏失败。
后续新增文案先检查真实字体覆盖；生成前后核对历史码点及像素语义，不能只看总字数。
`pixel_tests`直接检查历史“效/生”和新标题字形，并通过真实LVGL指针与IMU样本验证玩法、
坏输入/有界收敛、冷却重装、静止无重绘、遮挡/恢复、无IMU、分配失败与重复退出释放。
现有CI host检查加入 `pixel_tests`，不改变签名、分区或发布/OTA流程。
