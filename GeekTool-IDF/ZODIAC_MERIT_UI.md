# 星座运势与木鱼

2026-10-05，beta.23实现。`launcher.c/APPS` 在原17个App后追加 `app_zodiac`、`app_merit`；已有顺序、实体返回/计时映射和字体像素保持不变。

## 星座运势

`app_zodiac.c` → `zodiac_fetch_begin(sign,token)` → 独立FreeRTOS任务 / `network_http_get` → `zodiac_data_parse` → `zodiac_fetch_poll` → LVGL展示。

- 点星座符号、名称或“切换”进入12项列表；系统返回先收起列表，再退出App。五个分类标签直接选择综合/爱情/事业/财富/健康，选中项用暗红底标记；分类行独立显示五点评分及原始0至5分数。12个符号使用本地曲线绘制，依据 [Unicode 星座符号](https://www.unicode.org/charts/PDF/U2600.pdf)，不依赖缺失的emoji字形。正文用32px原生字库完整换行，中央矩形区域原生滚动，不截断长文。综合页仍列出幸运颜色、数字、贵人星座和宜/忌。
- 数据为[小小API星座接口](https://xxapi.cn/doc/horoscope)中文原文；英文系统界面使用紧凑日期标记 `CN`，加载时标记 `CN ORIGINAL`。GET参数只包含公开星座key、today和设备日期，无账号、密钥、位置或私有数据。沿用答案之书已有提供方，不增加收费依赖。
- 2026-10-05实查12种key均返回200、正确星座和10月5日；日期参数不改变接口schema。文档样例的幸运数字/颜色出现互换，实际响应类型正常；实现按实际字段展示，不自行调换。
- 使用已有ESP-IDF 6.0.1 HTTPS证书包，禁重定向，6秒I/O超时、最多两次传输共享8秒预算，8KiB响应缓冲。服务解析校验200业务码、所选星座、严格UTF-8、字段容量及0至5整数评分；未知评分显示 `-- / 5`。设备日期有效时只接受当天日期，防旧响应冒充今日。进入/选星座/刷新联网；可见页跨日自动更新。2026-10-07修正校时跨日后的失败/离线页也刷新，具体传输预算、取消与本地验证见[联网恢复逻辑](./NETWORKING.md)。没有离线随机运势。
- 取消只推进generation，旧任务自行关闭连接/释放内存。快速切换遇到BUSY时在UI期限内等待旧任务退出，再发所选星座请求，不并行堆任务。离线、HTTP失败、超时、无内容和缺字各显示明确状态；刷新可重试。隐藏页停止poll，退出取消请求并清空UI指针。
- 字体复用 `font_answer_32` 和3755字CJK fallback。12份真实响应检出“橘羯逅邂馨”缺字，加入 `artwork/zodiac/extra-glyphs.txt`，由 `gen_answer_font.swift` 生成；原309字的bitmap逐字未改变。真实接口去重字集保存在 `tests/lifestyle/horoscope_glyphs.txt`，覆盖当天全部12种响应的5类文本及幸运字段。未来遇到字库外内容明确提示，不显示方块。共享24px字体增加32字，原1460字bitmap未改变。

## 木鱼

`app_merit.c/knock`由木鱼触摸或右上PWR短按触发：计数加1 → `功德+1`（英文 `MERIT +1`）上浮/淡出与木鱼/木槌运动 → `audio_out_knock`异步播放。

- 每次有效敲击独立计数；提示完整显示200ms后淡出，620ms结束，上浮18px；连敲重新起步。木槌在敲击时落下，再回弹，木鱼小幅下沉。上限999,999,999，避免溢出。静止页不持续重绘，遮挡/锁屏停止动画时钟与按键积压。
- 木鱼使用有鱼眼、雕纹、空腔开口的木质插画，原始生成素材、提示词及转换入口见 [素材说明](./artwork/merit/README.md)。288×192基线JPEG嵌入固件，沿用已有 [esp_jpeg](https://components.espressif.com/components/espressif/esp_jpeg/versions/1.0.5?language=en) 解码能力，进入页面仅解码一次到110,592B PSRAM，退出释放并丢弃LVGL图像缓存。图片内存分配/解码失败明确提示，计数和声音仍可使用；不更改FAT分区或用户表盘图片。
- `merit_store.c`使用独立NVS namespace `merit`、u32 key `count`。不移动分区、不改其他设置格式。2秒无敲击后合并保存；连续敲击最长20秒保存一次，失败重试至少间隔2秒；隐藏/退出再保存。突然掉电可能丢失尚未保存的末段计数。
- 没有旧记录时从0开始；读取错误或超范围记录显示 `--`，点击重试读取，不覆写未知旧值。写入失败显示保存失败并保留RAM计数，退出/重进仍尝试保存；并非伪装为已持久化。
- 复用ES8311/I2S输出worker和麦克风互斥 `audio_bus`。`merit_sound.c/merit_sound_fill` 合成180ms、16kHz单声道敲击：740/1217/2093/3461Hz非整数倍模态各自衰减，加短促撞击噪声与首尾包络，替代旧95ms双频音；这是合成音，非实录。`write_knock` 每128样本检查新敲击，用32样本（2ms）交叉淡化接入新音色，避免直接清零相位造成跳变；不积压整段播放队列，同一8ms处理窗口内过密请求合并为最新一次，计数逐次保留。I2S TX启用 `auto_clear_after_cb`，播放后的已消费DMA缓冲清零，worker等待时不循环残留PCM。闹钟/设置试听不会被木鱼打断。音量服从系统设置，系统静音优先；App内声音开关只控制本App。退出释放音频占用，下一App可使用麦克风。没有新增设备端音频资源文件或解码器。

### 2026-10-06 连敲杂音与持续播放修复（beta.27）

- 用户实机反馈：木鱼有杂音，疯狂按后声音持续响。代码确认两处缺口：ESP-IDF6.0.1的I2S默认不自动清空DMA，输出worker播放完成后仍保留启用的TX通道，因此空闲/供数不足时会循环旧缓冲；连敲直接 `done=0` 切断当前波形，首样本跳至零，造成突变。前者来自输出配置，后者来自切换方式，不通过降低音量或取消计数掩盖。
- `audio_out.c/hardware_init` 使用原生 `chan.auto_clear_after_cb=true`；`write_knock` 在当前128样本边界用2ms线性交叉淡化接入新敲击。沿用音色、采样率、180ms长度、最新一次请求合并、音量/静音、音频总线与异步退出。只有木鱼重触发使用淡化，闹钟/设置试听的PCM与时长保持原样。
- 核对的官方来源：[ESP-IDF6.0.1 ESP32-S3 I2S配置说明](https://docs.espressif.com/projects/esp-idf/en/v6.0.1/esp32s3/api-reference/peripherals/i2s.html)。同时检查本机对应版本 `i2s_common.h` 的默认值，以及 `i2s_common.c` TX发送完成回调中清零的时序；没有改动第三方驱动或依赖。
- 旧 `merit_audio_tests` 在每次worker通知等待时立即退出，漏检“页面保持打开、TX仍启用”的实际生命周期。现在模拟6×240样本的DMA循环，在worker进入空闲等待后继续发送两圈，检查残留音不重复；4000次密集请求停手后须到达空闲、再敲须恢复，逐次重触发边界保留旧波形的连续样本。旧代码的 `--idle-dma` 和 `--retrigger-boundary` 两项分别断言失败，修复后完整实际worker测试通过，保留取消、写失败释放、静音/音量、闹钟1300ms和试听80ms回归。
- ESP-IDF6.0.1/ESP32-S3本地构建通过，候选包4,091,808B，4MiB槽余102,496B。用户随后明确授权“提交发版”，修复已发布为 `v1.7-beta.27`，实际CI包4,125,280B，4MiB槽余69,024B；三个地址完整包版本/摘要一致，国内条件Range通过，精确回执见 [发布记录](./PORTING_NOTES.md#2026-10-06-v17-beta27-木鱼音频修复发布)。没有USB串口，本轮未烧录；主机DMA模型、构建与发布不能代替扬声器实机验收。最小复验：单敲、连续快速敲后完全停手、声音开启页保持停手至少2秒、再敲、退出后进入音频采集；检查无持续杂音、正常恢复与音频总线释放。
